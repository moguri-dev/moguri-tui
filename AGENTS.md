# Repository State

- This repository contains an initial executable macOS alpha, not the completed first milestone. `docs/setup.md` identifies implemented behavior and unavailable capabilities. Never describe the wider roadmap as implemented.
- `docs/implementation.md` is the canonical implementation specification. `README.md` retains the product feature inventory; `docs/architecture/decisions.md` is authoritative for the selected stack. Reconcile documentation with executable code/config once those exist.
- Moguri is built from zero with borrowed libraries; it does not fork OpenCode or Pi. The stack is Node.js 26, OpenTUI + React, Electron + React, and a Moguri-owned worker loop using maintained `@earendil-works/pi-ai`. D06 explicitly permits Node/PTY supervision for this checkpoint; Rust helpers remain unvalidated. Change decisions in `docs/architecture/decisions.md`.
- Before adding Moguri features, follow Phase 0: run the validation spikes listed in `docs/architecture/decisions.md` and record each pass or fail result with measurements under `docs/`.

# Implementation Constraints

- Work in the documented phase order and implement the smallest complete vertical slice across the local service, TUI, and desktop; do not pull items from "Later work"/"Deferred work" ahead of first-release acceptance checks.
- The local control plane is authoritative. TUI, desktop, and optional VSX clients must share one typed API, domain model, and event stream rather than owning client-only state or provider payloads.
- Add capability APIs in `packages/sdk`; CLI/TUI and desktop import that SDK. Keep its root and React entrypoints browser-safe, its Node runtime explicit, and verify all entrypoints in a packed external consumer with `npm run verify:sdk`.
- The current platform contract is `docs/architecture/sdk-platform.md`. Dark is the desktop factory theme. Optional repository indexing, context injection, subagents and evolution start off. Scripts/plugins cannot grant permissions or self-approve.
- Dependency caching and local tickets follow `docs/architecture/workspace-platform.md`. Cache plans bind exact manifest/lock digests; fresh advisories and SHA-512 gate reuse. Managed installs never run lifecycle scripts without a qualified SendBox boundary. PR observations and optional Linear imports are read-only.
- Session workspace behavior follows `docs/architecture/session-workspace.md`. Cmd/Ctrl+Enter holds prompts without running them. Read-only/side modes are service-enforced. Embed Ghostty; never implement a new VT parser/renderer or persist terminal input/output in command receipts or model context.
- User console ownership follows `docs/architecture/terminal-reattachment.md`. Reattach only the exact authenticated profile/root owner, never replay input or infer PID ownership. Explicit restart preserves user PTYs; ordinary stop closes known groups. Retain failed private cleanup and discard stale queued input across attachment generations.
- Compact composer/model controls follow `docs/architecture/model-controls.md`. Keep window/effort settings shared in the SDK, expose only qualified transport options and label context estimates; never invent exact token/cost telemetry or silently truncate history.
- OAuth, project-free chats and reviewed configuration follow `docs/architecture/engagement.md`. Ordinary project-free Local chats use the captured Home binding in `docs/architecture/project-free-execution.md`, never an inherited project or synthetic project. Suggestions need explicit source review; models cannot apply changes or authenticate. Attention read acknowledgement is not an answer or approval.
- Configured local models and startup provenance follow `docs/architecture/runtime-foundation.md`. Discovery never scans hosts or downloads weights; failed models never substitute another provider.
- Typed context follows `docs/architecture/context-inputs.md`. Aggregate snapshots require exact review, images normalize locally, and unsupported models must preserve context rather than silently drop it.
- Core SSH execution follows `docs/architecture/execution-transports.md`. Pin host/build/root identities, keep credentials scoped, record frames atomically and reconcile late results without replay or turning partial work into success. Unqualified remote side-panel/MCP transports stay blocked.
- Remote repository metadata follows `docs/architecture/remote-github-metadata.md`. Only explicit reviewed refresh may use the captured SSH account; retain peer/root/build provenance, never substitute controller `gh` or replay an interrupted job. Client attachments and linked-PR observation keep their disclosed control-plane boundary.
- Repository memory follows `docs/architecture/remote-repository-memory.md`. Session APIs bind actual Env/profile/peer/root; project/worktree APIs stay explicitly Local. Keep optional indexing/injection off, cache publication atomic, stale source text empty and original index intent non-replayable. A changed builtin MCP resource requires new user review.
- Managed Local worktrees follow `docs/architecture/managed-workspaces.md`. Resolve every filesystem surface and writer lease through the bound root; never fall back to the base checkout. Preserve partial Git intent, branches and session-independent artifacts.
- Artifact revisions use per-artifact retention keys and exact canonical source actors/digests. Project removal requires reviewed retain/export/delete choices; exported files are user-triggered client delivery, never agent filesystem authority or automatic instructions.
- Structured questions use owning-turn/revision checks and actual answer actors. User answers may atomically consume a saved draft and create an independent artifact; never infer answers from queued text, heuristic badges or model confidence, or convert them into permissions.
- Artifact repository publication binds the exact source set, canonical root, policy and optional new local branch/base. Persist intent before effects, preserve the real index/checkout, and reverify actual copied bytes/commit before project deletion. Partial or interrupted jobs never authorize deleting grants.
- Reviewed candidates follow `docs/architecture/candidate-workflows.md`: keep actual session cancellation ownership separate from independent artifact/job/result retention; lease both Local roots, recheck exact bases/bytes/policy, retain attempts versus publications and commit terminal record/job atomically. User acceptance is not model quality or permission advice; no implicit worktree/commit/branch deletion.
- Candidate retention follows `docs/architecture/candidate-cleanup.md`: permanent origin-session deletion or fresh exact linked-PR merge deletes candidate/generation proposal compartments after owned work settles. Archiving preserves them; first recorded PR associations never follow relinks. Ordinary artifacts and budget accounting remain independent.
- Owned generation follows `docs/architecture/candidate-generations.md`: one bounded fixed-model Local draft uses the existing tool-less worker/ledger and independently retained original snapshots/results. Model provenance never approves staging/application; missing receipts and deleted reports cannot authorize another paid call.
- Private owned-role continuation follows `docs/architecture/owned-role-protocol.md`: require actual retained acceptance, exact root-less read-only ownership and complete bounded/metered tool-less output. Later role context is explicit; this private transport cannot enable a public compound workflow or model-owned acceptance.
- Retained role observations follow `docs/architecture/role-sequences.md`: keep exact plans/steps/inputs/results in the independent report compartment, forbid continuation on unknown accounting, and never replay terminal work. Late results may improve an admitted step without resuming the partial sequence or becoming normal solver context.
- Internal owned roles use the existing control-plane worker/commit path. Reserve complete future escaped-result context before admission, recheck known accounting before preparation, and keep the Node executor separate from public compound/family/quality/acceptance gates.
- Final-role proposals follow `docs/architecture/role-proposals.md`: bind canonical actual-role origin into exact staging review, clone original input/raw-result grants into the independent candidate, and retain separate actual-user source acceptance. Editing clears attribution; critic data and provenance never approve code.
- Explicit model inspection follows `docs/architecture/model-evidence.md`: normal Copilot login/discovery/inference gains no metadata reads. Provider-declared family/vendor/version stays informational, scoped and ephemeral; it cannot enable independent critique, compound routing or Max.
- Owned role contracts follow `docs/architecture/owned-role-contracts.md`: bind versioned output checks and explicit earlier-result selections before admission, keep router explanations out of contracted solver context, and retain rejected/unknown work without continuation. A matching contract is not code quality, family proof or acceptance.
- Model admission must atomically retain a profile-owned budget reservation with model.started. Reconcile actual totals once; unknown/lost completion holds capacity through source deletion/restart. Finite controls require explicit estimated accounting and fresh configured USD rates; defaults cannot clear hard profile policy.
- Pre-reserved checkpoint mechanics follow `docs/architecture/winddown-primitives.md`. Resolve current authoritative controls, verify the exact undispatched envelope and retain model.started before yielding; never reserve twice or borrow the hold as approval. Reviewed Git helpers preserve captured inputs/index/HEAD and need real caller-owned policy, leases and durable partial/no-replay lifecycle.
- Planned holds follow `docs/architecture/budget-plans.md`: they are independent profile-owned capacity, not model calls or reports. Calculate complete same-turn sets with `planBatch`, then atomically append all events with their owner before yielding; never overlap prospective capacity. Transfer once with the exact entry/start and release only canonically undispatched holds after the actual owner ends. Never refund consumed/unknown work or relabel legacy entries.
- Profile scope is immutable per SDK/store/controller view. Preserve Default identities and secret namespaces; shared global policy, preferences and capacity remain root-owned. Switching never moves drafts, credentials or running work. Follow `docs/architecture/profiles.md`.
- Remote writer ownership uses the captured pinned SSH peer/canonical root, not Local mappings or target/profile aliases. Retain quarantine across unloaded-profile recovery; requested mode changes do not release a writer before actual acknowledgement.
- The composer exposes Env, Model, Autonomy level, and Budget. Factory defaults are Local, no selected model until provider login or local-model configuration, Manual, and Unlimited. Defaults can be overridden globally, per profile, per repo/project, and explicitly per session without weakening policy.
- Env offers Local (host execution), Sandbox (native SendBox), and Remote (agent execution and model calls on a user-configured SSH machine). Global user-only allowed-env policy can require Sandbox or Remote. New Local turns are then blocked, but already-running Local turns may finish. SSH is not itself SendBox process isolation; show the actual boundary and never silently fall back to Local.
- Fixed-model or `kupo` selection, env, and autonomy level are independent. `kupo` supports single, cascade, and critique/revision workflows across approved, available local and hosted models. Manual is default; Guided requires human confirmation. Explicit Autopilot/Max selection delegates automatic tool approvals, never hard-policy overrides. Follow `docs/architecture/session-github-workflows.md`; preserve old bounded selections until explicit consent, and keep Max's qualified decision layer separate from permissions.
- Router, critic, and decision-model output is untrusted advice until validated and authorized. Record every call and its cost, decision provenance, and cancellation outcome; never label a model decision as a user answer or let confidence override policy.
- Durable state is a typed, append-only, versioned event stream. Durable schema changes require migrations and restart-recovery coverage; never make users delete local state to upgrade.
- Keep ordinary artifacts independent of session retention, with candidates as the explicit session-owned exception. Keep profiles isolated, secrets in an explicit secret backend, and estimated, provider-reported, and billed costs in distinct fields.
- Session budgets default to unlimited tokens and spend, subject to stricter policy limits. Optional token/USD caps include every model role; unknown telemetry is not zero usage. kupo reserves wind-down budget and attempts an authorized checkpoint commit before exhaustion, without overriding approvals, exceeding the cap, or claiming a commit succeeded when it did not.
- Cancellation must propagate through owned work and preserve requested, acknowledged, completed, failed, and partial outcomes. Never record stopped or partially cancelled work as successful.
- Push, merge, rebase, branch deletion, scheduled work, and self-modification require explicit user action or policy.

# Change Contract

- Before a feature change, identify reused libraries and their licenses, new invariants/events, schema and migration impact, cross-client behavior, failure/cancellation behavior, and the tests that prove it.
- Test concurrency, cancellation failure, migrations, and restart recovery where relevant, not only happy paths; use generated fixtures without personal or customer data.
- Put durable architecture documentation under `docs/`. Update the relevant setup, configuration, architecture, or protocol document in the same change.
- Setup: `npm ci`. Build: `npm run build`. Type checks: `npm run typecheck`. Full local checks: `npm test` then `npm run test:e2e` after building. Audit: `npm audit --audit-level=moderate`. Phase 0: `npm run spike`.
- SDK package check after building: `npm run verify:sdk`. Platform primitive spike: `node scripts/platform-spikes.mjs`. Speech runtime preparation verifies a pinned native archive, never downloads model weights. Tests use generated recognizers, never a real microphone or personal credentials.
- Cache/native package-manager spike: `npm run spike:workspace`. It uses generated archives, a loopback mirror and script markers, never a live project install.
- Session/retention/Ghostty primitive spike: `npm run spike:sessions`. It uses generated encrypted compartments and hidden Electron, never a personal shell or clipboard.
- Model-control spike: `npm run spike:models`. It proves actual supported/ignored thinking options and context sizing using generated loopback requests, never live inference.
- Engagement spike: `npm run spike:engagement`. It proves the official MCP OAuth discovery/PKCE/resource/refresh primitives using generated loopback endpoints, never a personal login.
- Runtime/provider spike: `npm run spike:runtime`. It uses generated loopback inference and reports native executable presence separately from real VM/SSH qualification.
- SSH primitive: `npm run spike:remote`. It owns a generated rootless loopback server/keys, never changes system SSH services or uses personal identities. Native worker/restart coverage includes an actual control-plane SIGKILL.
- CI runs only for pushes to `main`. Do not trigger it on pull requests or working branches; run required verification locally.
- Focused checks use `node --import tsx --test tests/<name>.test.ts`; combine related selectors in one invocation. `npm test` includes the native TUI interaction test. Electron tests run hidden, use generated fixtures, and never open the real GitHub authorization page.
- `npm start -- --project /absolute/path` starts the built TUI; `npm run desktop` starts Electron. `npm run package:mac` builds development macOS arm64 artifacts. Never open an app/browser or complete personal authorization on the user's behalf.
- Node emits an experimental FFI warning for OpenTUI. Linux CI checks the portable foundation but skips macOS-only agent/UI execution; it is not proof of Linux release readiness.
